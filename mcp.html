Eval Method Atlas — MCP

MCP を入れる

Claude Desktop に、実験と評価の設計の道具を追加します。原稿の PDF やアイディアを渡して「評価はどう設計すればいい？」「この原稿の評価を点検して」と頼むと、採録論文の実態にもとづく提案と、参考にできる論文が返ります。

Getting started

拡張機能（Claude Desktop）

  1. 上の eval-method-atlas.mcpb をダウンロードします。登録や API キーは要りません。
  2. ダウンロードしたファイルをダブルクリックすると、Claude Desktop に追加する画面が出ます。「インストール」を押します。
  3. Claude に話しかけます。例：「~/Desktop/draft.pdf の評価の設計を点検して」「推薦のオフライン評価で、参考になる論文を 5 本」「ユーザースタディを入れるべきか、採録論文の実態を見て判断して」
  4. Claude が原稿を読んで研究の特性を選び、design_guide・review_design・reference_papers などを呼びます。答えには、採録論文での採用率（実態）と、勧めの根拠（統計学の性質・専門家の勧告）が分けて書かれます。

対応：macOS・Windows の Claude Desktop（Node.js は Claude Desktop に含まれます）。そのほかの MCP クライアントでは、server/index.mjs を node で起動する stdio サーバーとして登録できます。

Data

ファイルはどこへ行くか

原稿の PDF やアイディアは、Claude が読むだけです。Eval Method Atlas のサーバーは、拡張機能に同梱した公開データ（採録論文の書誌・リンク・判定のラベル）を手元で引くだけで、LLM を呼ばず、原稿をどこにも送りません。原稿を Claude に渡すことの扱いは、お使いの Claude の設定に従います。

公開データの中身と判定の問いは 研究と判定の問い にあります。ライセンスは CC BY 4.0 です。

困ったとき

  • 拡張機能が出てこない：Claude Desktop を最新版にして再起動してください。
  • 「研究の特性 ID ではありません」と出る：find_traits か suggest_traits で ID を探すよう、Claude に頼んでください。
  • 当てはまる論文が少ない：特性を 2〜3 個に減らすと母数が増えます。
  • そのほかは GitHub の Issues へ。
